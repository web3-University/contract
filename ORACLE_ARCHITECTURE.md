## 数据流详解

### 1. 请求阶段

```
用户/管理员
    │
    │ requestCourseCompletion(student, courseId, courseName)
    ▼
CourseNFTOracle
    │
    │ 创建 Chainlink Functions Request
    │ - 设置 JavaScript 源代码
    │ - 传入参数: [studentAddress, courseId]
    │ - 设置 gasLimit, subscriptionId, donId
    ▼
Chainlink Router
    │
    │ 发送到 DON
    │ 消耗 LINK
    ▼
记录请求状态
    │
    │ 发出 RequestSent 事件
    └──▶ 返回 requestId
```

### 2. 链下执行阶段

```
Chainlink DON 节点
    │
    │ 接收请求
    ▼
JavaScript 运行环境
    │
    │ const studentAddress = args[0]
    │ const courseId = args[1]
    ▼
发起 HTTP 请求
    │
    │ GET /courses/{courseId}/students/{address}/completion
    ▼
后端 API
    │
    │ 查询数据库
    │ 验证课程完成状态
    ▼
返回响应
    │
    │ { completed: true/false, ... }
    ▼
JavaScript 处理
    │
    │ if (completed) return encodeUint256(1)
    │ else return encodeUint256(0)
    ▼
DON 节点达成共识
    │
    └──▶ 准备回调
```

### 3. 回调阶段

```
Chainlink DON
    │
    │ fulfillRequest(requestId, response, error)
    ▼
CourseNFTOracle
    │
    │ 解码响应
    │ uint256 status = decode(response)
    ▼
验证结果
    │
    ├─ status == 1 (完成)
    │   │
    │   │ nftContract.mintCertificate(...)
    │   ▼
    │  SimpleYDNFT
    │   │
    │   │ 铸造 NFT
    │   │ certificates[tokenId] = {...}
    │   ▼
    │  发出 NFTMinted 事件
    │   │
    │   └──▶ 发出 RequestFulfilled(success=true, tokenId)
    │
    └─ status == 0 (未完成)
        │
        └──▶ 发出 RequestFulfilled(success=false, tokenId=0)
```

## 组件职责

### CourseNFTOracle 合约

**核心职责**:
- 管理课程完成验证请求
- 与 Chainlink Functions 交互
- 处理预言机回调
- 触发 NFT 铸造

**关键方法**:
- `requestCourseCompletion()`: 发起单个请求
- `batchRequestCourseCompletion()`: 批量请求
- `fulfillRequest()`: 处理回调（由 Chainlink 调用）
- `updateSource()`: 更新 JS 源代码

### SimpleYDNFT 合约

**核心职责**:
- 管理 NFT 铸造和转移
- 存储课程证书信息
- 提供 NFT 查询接口

**关键方法**:
- `mintCertificate()`: 铸造证书 NFT
- `getCertificate()`: 查询证书信息
- `hasCertificate()`: 检查证书存在性

### Chainlink Functions

**核心职责**:
- 执行链下 JavaScript 代码
- 调用外部 API
- 达成去中心化共识
- 回调链上合约

**运行环境**:
- JavaScript V8 引擎
- HTTP 请求能力
- 密钥管理（secrets）

### 后端 API

**核心职责**:
- 验证学生课程完成状态
- 管理学生学习进度
- 提供可靠的数据源

**API 规范**:
- RESTful 接口
- JSON 响应格式
- 适当的错误处理

## 错误处理流程

```
请求发送
    │
    ├─ 参数验证失败 ─────▶ revert InvalidAddress/InvalidCourseData
    │
    ├─ 重复请求 ─────────▶ revert RequestAlreadyPending
    │
    ├─ LINK 不足 ────────▶ Chainlink 抛出错误
    │
    └─ 成功发送 ─────────▶ 继续

回调处理
    │
    ├─ 未知请求 ID ──────▶ revert UnexpectedRequestID
    │
    ├─ API 错误 ─────────▶ success=false, 记录错误
    │
    ├─ 验证失败 ─────────▶ success=false, 不铸造 NFT
    │
    ├─ NFT 铸造失败 ─────▶ try-catch, success=false
    │
    └─ 全部成功 ─────────▶ success=true, tokenId 返回
```

## 性能优化点

### 1. Gas 优化
- 使用 `calldata` 而非 `memory`
- 批量处理减少交易次数
- 优化存储布局

### 2. 并发处理
- 支持多个请求同时处理
- 请求状态独立管理

### 3. 缓存策略
- 前端缓存已验证的状态
- 后端缓存学生进度数据
